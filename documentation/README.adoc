= SmallRye Reactive Messaging documentation

The documentation is AsciiDoc, laid out like the Quarkus guides, and published on
https://smallrye.io/docs/smallrye-reactive-messaging/latest/[smallrye.io]. The site pulls it from this
repository: the `main` branch every night, and each release once it is tagged.

== Where things are

[cols="1,2"]
|===
|`src/main/asciidoc/**/*.adoc` |One page per file. The path is the page's address: `kafka/kafka.adoc` is published at `/docs/smallrye-reactive-messaging/<version>/kafka/kafka/`.
|`src/main/asciidoc/_nav.yml` |The sidebar: page order and sections. A new page must be added here.
|`src/main/asciidoc/_attributes.adoc` |Attributes every page includes (ids, paths, the versions the pages mention).
|`src/main/asciidoc/_partials/` |Pieces included by several pages, such as the Pulsar client configuration tables (`just update-pulsar-config-docs` regenerates them).
|`src/main/asciidoc/images/` |Images, referenced as `image::images/name.png[]`.
|`src/main/java/` |Code examples. They compile with the build, so they cannot go stale.
|`target/connectors/` |The connectors' attribute tables, generated by `smallrye-connector-attribute-processor` and unpacked by this module's build; pages include them from `{generated-dir}`.
|===

== Writing a page

[source,asciidoc]
------
= Page title
:version-root: ../
include::{version-root}_attributes.adoc[]

Text...

== A section

Link to another page with xref:kafka/kafka.adoc[Kafka], or to a section of it with
xref:kafka/kafka.adoc#a-section[].

[source,java]
----
include::{examples-dir}/kafka/inbound/KafkaDeadLetterExample.java[tags=code,indent=0]
----

include::{generated-dir}/smallrye-kafka-incoming.adoc[]
------

* A page in a subdirectory sets `:version-root:` (`../` per level) before including `_attributes.adoc`.
* Section ids are Quarkus-style: `== Custom Scalars` gets the id `custom-scalars`.
* Include part of an example by marking it with `// tag::code[]` and `// end::code[]`.
* Admonitions: `NOTE:`, `TIP:`, `IMPORTANT:`, `WARNING:`, `CAUTION:`.

== Previewing

Pull requests that change the documentation are rendered with the smallrye.io site by the
`Documentation` workflow, which fails on a broken include or a page that does not render. The
rendered site is attached to the workflow run as the `docs-smallrye-reactive-messaging` artifact.

To see the documentation the way smallrye.io shows it while you write it, run from this repository:

[source,bash]
----
./mvnw -Pdocs-preview
----

and open http://localhost:8080/docs/smallrye-reactive-messaging/main/. Pages and included examples are published again
when you save them; refresh the page. Only Java is needed: the profile runs the
https://github.com/smallrye/smallrye.github.io/tree/develop/tools/docs[smallrye.io docs tools]
with https://www.jbang.dev[JBang]. Where JBang is installed, `jbang docs-preview@smallrye/smallrye.github.io`
does the same, and takes options such as `--port` or `--site <a smallrye.github.io checkout>`
(see `--help`).

The connector attribute tables come from the latest release, or from your own build when there is
one: run `./mvnw -pl documentation -am package -DskipTests` first to see changes to them.
